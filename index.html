The Governing Rule

Autonomy matched to consequence

The core question of agent governance is not whether an agent holds an API key, but what operational consequence it threatens. Our runtime divides every proposed intent into three distinct tiers:

Proposed Action Default Handling What the Operator Sees
Tier 1: Read & Analyze
Analyze internal documents, aggregate metrics, query databases.
 Proceed Autonomous

Proceeds under scoped read access, ephemeral tokens, and active telemetry capture.
Observable Telemetry:
• Live activity trace and token consumption rate
• Exact document/DB provenance & chunk references
• Operator interrupt control (soft cancel / kill thread)
Tier 2: Bounded Mutation
Modify staging configs, draft pull requests, update non-critical records.
 Proceed if Verified

Proceeds only if preauthorized, isolated in sandbox, and rollback-tested prior to execution.
Validation Guardrails:
• Target resource boundary, AST schema limits, and spend caps
• Automated canary run and pre-flight rollback test receipt
• Dynamic stop conditions (aborts on state variance)
Tier 3: High-Impact Execution
Production migration, customer batch communication, fund disbursement.
 Synchronous Pause

Mandatory hold for a named human approver or quorum. Zero network mutation without signed token.
Human Decision Dossier:
• Exact targets, serialized argument diff, and financial terms
• Evidentiary chain, missing prerequisites, and risk profile
• Attributable Approve, Reject, or Request Remediation controls
ℹ
Reversible does not mean safe. Actions dynamically escalate to stricter tiers when: data classification changes (e.g., encountering PII/secrets), privilege escalation is detected, model uncertainty rises above threshold, or cumulative blast radius exceeds aggregate limits across a multi-step workflow.
